# 桂电毕设 Agent 工作流

## 1. 输入材料审计

让 Agent 先读取并列出已有材料：

- 学校格式要求、封面、声明、提交材料清单。
- 项目代码仓库、README、运行截图、测试结果、实验日志。
- 已有开题报告、任务书、中期材料、答辩 PPT 或草稿。
- 参考文献库、阅读笔记、论文 PDF。
- 指导老师或学院给出的额外要求。

输出应包括：

- 已有材料清单。
- 缺失材料清单。
- 哪些内容可以直接支撑论文。
- 哪些内容必须补实验、补截图、补引用或补说明。

## 2. 证据表

每个重要论断都要绑定证据。建议让 Agent 生成表格：

| 论文内容 | 需要证据 | 当前证据 | 风险 |
| --- | --- | --- | --- |
| 系统需求 | 需求说明、用户场景、功能列表 | 待补 | 不能空写 |
| 模块设计 | 架构图、核心代码、接口说明 | 待补 | 需要截图或图 |
| 实验结果 | 指标表、日志、配置、数据划分 | 待补 | 不能编数 |
| 系统测试 | 测试用例、截图、异常处理 | 待补 | 需要可复现 |

没有证据的地方，只能写成计划、设计、限制或待完成，不能写成已经完成。

## 3. 大纲

通用本科毕设结构可以从这里开始：

1. 绪论
2. 相关技术与理论基础
3. 需求分析与总体设计
4. 核心模块设计与实现
5. 系统测试或实验结果分析
6. 总结与展望

如果是算法类项目，可以把第 5 章写成实验设计与结果分析；如果是系统类项目，可以把第 5 章写成功能测试与性能测试。

## 4. 写作顺序

推荐顺序：

1. 写项目背景和任务目标。
2. 写真实系统或算法流程。
3. 写实现细节和关键代码对应关系。
4. 写测试、实验、截图和结果。
5. 写摘要、结论、展望。
6. 补参考文献和格式。
7. 生成 Word 并导出 PDF 检查。

不要一上来直接让 Agent 写完整论文；先做证据表和大纲，后续返工会少很多。

## 5. 最终检查

最终交付前至少检查：

- 标题、学院、专业、班级、姓名、学号、指导老师是否正确。
- 摘要和关键词是否与正文一致。
- 目录是否自动更新。
- 正文标题层级是否规范。
- 图表编号是否连续。
- 参考文献是否都被正文引用。
- PDF 页面是否有错位、空白页、图片遮挡、表格溢出。
